用 Claude Code 建立個人學術網站：一個研究者的實作紀錄

Created on May 08, 2026

2026   ·   AI工具   ClaudeCode   Jekyll   網站建置   ·   sharing

身為一個統計背景的研究者，我對前端開發一直保持「夠用就好」的態度。這次架設個人學術網站，我選擇用 Claude Code 作為主要工具，從頭到尾輔助整個建置流程。這篇文章記錄這段過程。

起點：選 al-folio 主題

Jekyll 的 al-folio 主題專為學術用途設計，支援 BibTeX 論文管理、CV 渲染、部落格分類等功能，是學術圈常見的選擇。我在 GitHub 上 fork 了這個 repo，並把它當作起點。

第一個決策是移除 Decap CMS。al-folio 預設整合了一個內容管理介面，但對我來說它引入了不必要的複雜度。我改用純 Markdown 工作流——直接編輯 .md 檔案，透過 git push 部署，反而更乾淨。

Claude Code 的角色

整個過程我幾乎沒有直接手寫 HTML 或 Liquid 模板語法。我的工作方式是這樣的：

  1. 描述需求：「幫我在 About 頁面加入研究興趣和目前研究方向」
  2. Claude Code 找到對應檔案、寫出修改、解釋原因
  3. 我確認、測試、push

這種分工讓我可以專注在「要做什麼」，而不是「怎麼寫 Liquid 語法」。

最有感的功能是中英雙語切換。網站的主要語言是中文，但我希望國際讀者也能閱讀。Claude Code 設計了一套機制：navbar 右上角加一個 ZH/EN 按鈕，切換時透過 CSS 的 data-lang 屬性控制顯示，語言偏好存在 localStorage，頁面重整後不會重置。

這個功能橫跨了 CSS、JavaScript、Liquid 模板、YAML 資料檔共十幾個檔案，手動實作估計需要半天，Claude Code 大約用了十分鐘。

遇到的問題

過程並非一帆風順。幾個值得記錄的坑：

ImageMagick 編碼錯誤：Windows 中文系統的 Ruby 4.0 在執行 Jekyll 的圖片處理插件時，會因為錯誤訊息包含非 UTF-8 字元而崩潰。解法是在本地設定檔關掉 imagemagick，部署到 GitHub Pages 時不受影響。

縮圖路徑失效：專案卡片的圖片路徑指向不存在的目錄，導致全部顯示破圖。Claude Code 直接找出根本原因，而不是繞過問題。

navbar 品牌名稱擠壓：al-folio 預設在非首頁的 navbar 左側顯示作者姓名，造成欄位擁擠。一行改動移除了這個行為。

工作方式的反思

用 Claude Code 建網站，和用 Claude.ai 對話的體驗有根本的不同。它能直接讀寫檔案、執行指令、看到錯誤訊息後自己修，而不只是給你貼一段程式碼讓你自己處理。

對於像我這樣「有想法但不想深陷實作細節」的研究者來說，這個工具的價值在於：它把我從「學 Liquid 語法」這件事解放出來，讓我可以把時間花在「網站要呈現什麼內容」上。

網站還在持續建置中，但這段過程已經讓我對 AI 輔助開發的可能性有了更具體的感受。
