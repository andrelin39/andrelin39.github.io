用 Claude Code 建立個人學術網站：從挫折到成就感的 AI Agent 體驗

Created on May 08, 2026

2026   ·   AI工具   ClaudeCode   Jekyll   網站建置   ·   sharing

老實說，這個網站我「建」過好幾次。

第一次是找 Claude AI 對話，請它幫我規劃。它推薦了 Hugo + Hugo Academic 主題，部署到 GitHub Pages。聽起來很美好——直到推送的時候開始出問題。Claude AI 叫我去改某些設定檔，但我根本找不到那些檔案在哪裡。我們就這樣在「你去改 X 檔案」「我找不到 X 檔案」之間來回了好幾輪，最後無聲地放棄了。

第二次是 WordPress。介面直覺，外掛豐富，不用管什麼 git。但客製化到一定程度就像在跟系統搏鬥——不是跑版就是外掛衝突，主題一更新又壞掉，折騰半天最後還是不了了之。

這次不一樣了。

先想清楚，再動手

這次的起手式是在 Claude AI 的對話介面裡先規劃再執行：確定要用 al-folio 主題（Jekyll，學術圈常見選擇）、討論要哪些頁面、中英雙語怎麼設計、工作流要多簡單。等到方向清楚了，才把任務交給 Claude Code 去執行。

這個「先想、後做」的節奏，讓整個過程出乎意料地順。

Claude Code 的感覺完全不同

Claude Code 是跑在終端機的 CLI 工具，和 Claude AI 對話最本質的差異在於：它不需要我當中間人。

它直接讀你的檔案、寫入修改、跑指令、看到報錯後自己追根本原因再修。我說「幫我加中英語言切換」，它就自己找出需要動到哪些檔案——CSS、JavaScript、Liquid 模板、YAML 資料、navbar 的 include——然後一口氣改完，問我要不要 commit。

這個功能橫跨十幾個檔案，手動實作大概要半天。Claude Code 十分鐘搞定，我只負責在瀏覽器確認效果然後說「沒問題，push」。

過程中當然也踩了幾個坑：Windows 中文環境的編碼問題讓 Jekyll 直接崩潰、專案縮圖全部 404、navbar 被作者姓名擠到變形。但每個問題都是描述現象、等它找原因、確認修法，沒有一次要我自己去翻文件。

這才是 AI Agent 該有的感覺

回頭看，WordPress 失敗在「系統太複雜我兜不住」，對話式 AI 失敗在「我要自己搬磚」。Claude Code 的體驗是：我負責做決定，它負責執行，這個邊界劃得很清楚。

對一個不以寫程式為業的研究者來說，這種感覺很珍貴——終於可以把時間花在「這個網站要呈現什麼」，而不是「這行 Liquid 語法哪裡寫錯了」。

網站還在建置，但這段過程本身就值得記一筆。
