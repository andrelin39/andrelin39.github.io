用 Claude Code 建立個人學術網站:從挫折到成就感的 AI Agent 體驗

Created on May 08, 2026

2026   ·   AI工具   ClaudeCode   Jekyll   網站建置   ·   notes

老實說,這個網站我「建」過好幾次。

第一次是透過 Claude 的對話介面尋求協助,請它幫我規劃整體架構。它推薦了 Hugo 搭配 Academic 主題、部署至 GitHub Pages 的組合——聽起來相當理想,直到實際推送階段才開始遭遇困難。Claude 指示我修改特定的設定檔,但我始終無法在專案中定位到那些檔案。於是我們陷入了「請修改 X 檔案」與「我找不到 X 檔案」的反覆對話,最終在無聲中放棄。

第二次嘗試是 WordPress。介面直觀、外掛生態豐富,也無需處理 git 操作。然而客製化一旦超過某個門檻,便彷彿在與整個系統角力——不是版面錯位,就是外掛之間相互衝突;主題一經更新,既有設定又付諸流水。幾經周折之後,這個版本同樣不了了之。

這次的經驗截然不同。

先思考,再行動

這次的起手式,是先在 Claude 對話介面中完成完整的規劃,再進入執行階段。我與 Claude 反覆討論了幾項關鍵決策:選用 al-folio 主題(基於 Jekyll,是學術社群中相當主流的選擇)、確認網站需要哪些區塊、中英雙語架構應如何設計、日常更新的工作流要簡化到什麼程度。待整體方向清晰後,才將實作任務交付給 Claude Code。

這種「先構思、後執行」的節奏,讓整個建站過程順暢得超乎預期。

Claude Code 帶來的根本性差異

Claude Code 是運行於終端機的命令列工具,它與 Claude 對話介面最本質的差異在於:它不需要我擔任中介者。

它能直接讀取專案中的檔案、執行修改、運行指令,並在遭遇錯誤時自行追溯根因並修正。當我提出「請為網站加入中英語言切換功能」這樣的需求,它會自主分析出涉及的所有檔案——CSS、JavaScript、Liquid 模板、YAML 資料檔、navbar 的 include 元件——並一次性完成所有修改,最後僅需我確認是否 commit。

這項功能橫跨十餘個檔案,若以手動方式實作,大約需要耗費半天。Claude Code 在十分鐘內便完成全部工作,我所需要做的,只是在瀏覽器中驗證成果,然後回覆一句「沒問題,push」。

過程中自然也遭遇了若干阻礙:Windows 中文環境的編碼問題曾使 Jekyll 完全崩潰、專案縮圖全部回傳 404、navbar 被作者姓名擠壓而變形。但每一個問題的處理方式都是相同的循環——我描述現象、等待它分析根因、確認修正方案——從未需要我親自翻閱技術文件。

這才是 AI Agent 應有的樣貌

回顧這幾次嘗試,WordPress 的失敗源於「系統過於複雜,我無法駕馭」;對話式 AI 的失敗則源於「我必須親自執行每一個步驟」。Claude Code 所提供的體驗,則是清晰地劃分了角色:我負責決策,它負責執行。

對一位本業並非程式開發的研究者而言,這樣的協作模式格外珍貴。我終於得以將時間投注於「這個網站應當呈現什麼內容」,而非「這行 Liquid 語法究竟錯在何處」。

網站尚在持續建置之中,但這段過程本身,已值得記錄一筆。
